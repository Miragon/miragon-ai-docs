tools:
  - tool: Skills
    text:
      - Your coding agent in Claude Code combines two skills. The bpmn skill from the bpmn-cli plugin sets Camunda 7 or Camunda 8 attributes by element id and keeps the drawn layout, and `bpmn validate --strict` reports each deploy blocker with the command that fixes it before the file reaches the engine.
      - The operate skill then deploys the model to Camunda 7, CIB seven or Operaton and runs one test instance to the end. If it hits an incident, `operate wait` stops with exit code 9. Neither skill writes worker or delegate code; bpmn-to-code's skills do.
    status: Early. bpmn-cli 0.7.0 and operate 0.7.0 are pre-1.0 (as of 2026-10-14). Camunda 8 files can be edited and validated, but no skill runs them. Both skills install from the public plugin marketplaces in [Miragon/bpmn-cli](https://miragon.github.io/bpmn-cli/claude-code-plugin) and [Miragon/operate](https://miragon.github.io/operate/agents#claude-code-plugin).
  - tool: bpmn-to-code
    text:
      - The Gradle and Maven plugin generates Kotlin or Java constants from your BPMN models, such as element ids, topics, job types and message names. Workers and process tests reference them, so a task renamed in the model breaks the next build and no longer leaves an instance waiting for its worker.
      - Its Claude Code plugin sets up the build plugin, replaces hardcoded strings and writes one worker, process adapter or process test at a time against the generated API, with delegates or external tasks on Camunda 7, CIB seven and Operaton, or job workers on Camunda 8. The use case a worker calls stays your team's code.
    status: Released. bpmn-to-code 6.5.0 (2026-10-18) is on the Gradle Plugin Portal and Maven Central under the MIT licence. Its Agent Skills are beta, and C# output and the command-line tool are experimental.
  - tool: Solution templates
    text:
      - "[pulse-starter](https://github.com/Miragon/pulse-starter) and [mcp-toolkit-starter](https://github.com/Miragon/mcp-toolkit-starter) are GitHub template repositories that start your own MCP server. Neither contains process automation code such as job workers or engine setup."
      - pulse-starter combines the Pulse modules for Camunda 7, CIB seven and Operaton with modules for your own systems, such as your ERP, and builds a Docker image with OAuth, health checks, `/metrics` and read-only defaults. A new module starts as a copy of the example module, and guard tests report a missed wiring step. mcp-toolkit-starter is the minimal base for an MCP server with interactive widgets and no BPM modules.
    status: pulse-starter is MIT-licensed and pins Pulse's `@miragon/pulse-*` packages at 0.21.0 (as of 2026-10-16). They are pre-1.0 and release about weekly, often with breaking changes. mcp-toolkit-starter builds on the Miragon MCP Toolkit 2.8.1 and has no licence yet.
