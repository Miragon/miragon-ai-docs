steps:
  - title: Connect
    text: Pulse CLI talks to the engine's REST API. A profile holds the URL and the Basic auth, OAuth or bearer token settings, and a project file (.pulse-cli.json) shares the profiles with your team.
  - title: Triage
    text: pulse-cli status reads the engine in parallel requests and groups root incidents by activity and message, each with a root-cause line from the stack trace.
  - title: Inspect
    text: pulse-cli inspect shows where one instance waits and why, across called sub-instances, with its incidents and variables.
  - title: Act
    text: Every finding names the next command to run, and --dry-run previews any write first.
commands:
  - icon: activity
    eyebrow: Read
    title: pulse-cli status
    text: Engine triage. Root incidents by root cause, overdue jobs, external task topics with waiting tasks or expired locks, and failed batches.
  - icon: search
    eyebrow: Read
    title: pulse-cli inspect
    text: Where one instance waits and why, across called sub-instances. Select it by id, business key or the latest instance of a definition.
  - icon: clock
    eyebrow: Read
    title: pulse-cli wait
    text: Replaces sleep and poll loops. An incident ends the wait at once, with exit code 9.
  - icon: play
    eyebrow: Write
    title: pulse-cli advance
    text: Completes the user task, external task, message or timer the instance waits for. You name the instance, for example by business key, not the task.
  - icon: refresh
    eyebrow: Write
    title: pulse-cli retry
    text: Sets the retries behind open incidents. After you deploy a fix, --now runs the jobs again at once.
  - icon: package
    eyebrow: Write
    title: pulse-cli deploy
    text: Deploys only the changed .bpmn, .dmn and .form files and can start an instance right away.
