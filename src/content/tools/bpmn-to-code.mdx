compare:
  before:
    title: Today
    items:
      - Workers carry their topic or job type as a string copied from the modeler
      - A topic renamed in the model still compiles, and the instance waits for a worker that never comes
      - Process tests type element ids by hand and fail only when they run
      - A service task without a topic shows up when the engine rejects the deployment
  after:
    title: With bpmn-to-code
    items:
      - Workers reference a generated constant for each topic and job type
      - The next build after the rename names every worker that still uses the old constant
      - A ProcessPath built from the generated flow nodes stops compiling when the model no longer has that path
      - Generation stops on a service task without implementation, a message without a name or a timer without a definition
steps:
  - title: Add the plugin
    text: Apply the Gradle plugin or bind the Maven goal, and set the engine, the output language and the package.
  - title: Generate
    text: generateBpmnModelApi checks every model against the built-in rules, then writes one ProcessApi object per BPMN file and shared objects such as ServiceTasks, Messages and Errors.
  - title: Reference
    text: Workers, process adapters and process tests use the constants and the typed FlowNodes instead of strings.
  - title: Rebuild
    text: After a change to the model, the next build regenerates the API, and the compiler points at every line that no longer fits.
result:
  - icon: shield
    title: Validation before generation
    text: Built-in rules stop the run on an error and write nothing. The testing library bpmn-to-code-testing adds rules of your own, such as your modelling conventions.
  - icon: route
    title: Process paths that compile
    text: ProcessPath walks a route through the generated flow nodes and hands its ids to the flow assertion of your test library.
  - icon: package
    title: No engine dependency
    text: The generated code is plain constants and objects. Kotlin and Java need only bpmn-to-code-runtime, which the Gradle plugin adds for you.
  - icon: refresh
    title: Same model, same code
    text: The output depends only on the BPMN files and the configuration, so a CI job can regenerate and fail when committed code is out of date.
  - icon: code
    title: Kotlin, Java or C#
    text: Kotlin and Java use the small runtime library. C# output is experimental and carries its types in each file.
  - icon: globe
    title: Without a build
    text: The web app takes up to three BPMN files in the browser, and the Docker image miragon/bpmn-to-code-web runs it on your own infrastructure.
